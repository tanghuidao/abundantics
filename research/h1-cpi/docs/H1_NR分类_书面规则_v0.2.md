> 日期：2026-09-03。用途：把 N/R 分组从 9 个试点品类扩展到 CPI 全样本的**归类依据**，
> 作为「理论驱动三分法 + 盲分类」的书面规则，供任何后续复核者按同一规则复现归类。
> 配套实现：`token-parity/h1_build_mapping.py`（分类 + 叶子硬检查 + 层级树生成），

## 一、归类规则（一句话，可复核）

> **一个 CPI 品类，若其主要成分是「需现场提供、无法预先库存的人力劳动服务」，归 N；
> 若其主要成分是「可数字复制、或可全球贸易/离岸规模化生产的商品与服务」，归 R；
> 两者混合、或主要驱动力来自外生/管制因素、或依据不明的，归「中性」，不强行二选一。**

展开判据（可操作化）：

| 分组 | 判据（满足其一即可入组，否则不强行入组） | 典型域 |
|---|---|---|
| **N（难自动化·稀缺迁移上涨）** | ① 需现场提供、无法预先库存的人力劳动服务；② 受知识产权/牌照/管制保护的稀缺供给 | 医疗照护、教育、托儿、住房服务、个人服务、维修保养、保险、外食、公共交通 |
| **R（可自动化·丰裕化下跌）** | ① 可数字复制；② 可全球贸易/离岸规模化生产的商品与服务 | 电子硬件、软件、通信/影音、家电家具、服装鞋类、玩具、运动器材、汽车零配件 |
| **中性** | N/R 判据混合，或主要驱动力为外生（食品/能源）、管制（公用事业）、税/费、奢侈品/位置性与可贸易冲突的 | 食品、能源、公用事业、烟酒、珠宝手表、航空 |
| **排除** | 非「品类」的统计集合：大类、交叉聚合（`less X` 类）、含已入组子项的聚合层、基准序列 | SA0、SAH、SAM、SACL*、SAS、SETG… |

**硬约束：不强行二选一。** 依据不足的品类一律「中性」，宁可缩小检验集、不可污染分组。

## 二、盲分类协议（防「为结果好看而分类」）

1. **归类先于 δ̂ 计算**：本表 N/R/中性 归类完成并提交的时间戳，**早于** `h1_analyze.py` 首次对这些新序列产出 δ̂（届时本仓库尚未拉到新序列价格数据，归类者客观上不可能看到结果）。
2. **时间戳留痕**：归类数据的提交 commit message 注明「盲分类完成时间」，与后续「数据拉取」「δ̂ 计算」的 commit 分离。
3. 与教科书排除同一纪律（说明书 A 排除决定早于显著性增强发现，无因果关联）。
4. **下钻子项不机械继承父类标签**：聚合层拆开后的每个子项，**独立套用第一节判据重新判定**，不得因为父类是 N/R 就默认子项同组。实例：SEHL（室内家居）是 R，但其子项 SEHL02（室内植物花卉）因鲜活易腐、本地生产为主，独立判定为「中性」。

## 四、明细优先 + 叶子硬检查（程序化，不靠肉眼）

1. 新扩展品类进入 N/R 检验集的前提 = 是 BLS cu.item 树中的**叶子**（无子项）。
2. 含子项的聚合层 → 归「排除」，不重复入组。
3. **该判定由 `h1_build_mapping.py` 程序化强制**：脚本内置 `HAS_CHILDREN` 聚合集合，
   校验阶段断言「任何 N/R 品类的 item_code 不得出现在 HAS_CHILDREN 中」，违反即 fail loud。
   —— 130+ 品类靠人眼过一遍容易漏，必须机器判。

> **叶子边界的定义见第六节**（「数据覆盖决定深度」，而非「卡在第几层」）。

## 五、层级树来源与核验链（v0.2 已更新 BLS 通道认知）

- **BLS 通道现状（2026-09-03 实测修正）**：
  - `download.bls.gov` 扁平文件（cu.item / cu.series / cu.data.*）对**本地 AND GitHub Action runner 均 403**（Akamai 地域封锁），不可直连。
  - `api.bls.gov` v2 API（需 `BLS_API_KEY`）**仅对 runner 可达**，本地开发环境不可直连。
  - 本地唯一兜底 = **WebFetch（走服务端网络）** 读 `download.bls.gov` 扁平文件（会截断，但能精确返回单/多项）。
- **seriesID 存在性核验**：由 `h1_verify_series.py` 在 Action 上走 BLS v2 API `catalog=true` 通道（返回 series_title 元数据；**不返回 begin_year**，数据起始年份改用「窗口内最早观测年份」回填）。
- **叶子性核验**：本地 WebFetch 读 `cu.item`（item_code / item_name / display_level / selectable / sort_sequence，无显式 is_leaf 字段，靠 display_level 序列 + 前缀关系推断父子）+ `cu.series`（含 ELI 层 series）交叉验证。
- 新品类 `状态` 先设 **`待核实`**（fetch 层只抓 `已核实`），待 Action 核验 seriesID 存在性 + 回填起始年份后，再逐批翻 `已核实`。

## 六、叶子边界原则（v0.2 新增）——「数据覆盖决定深度」

> **叶子边界 = 沿 BLS 层级持续下钻，直到不存在「已发布、且数据覆盖世纪窗口（≤1998 起）」的更细子项为止。**

换句话说：**边界由「数据覆盖」决定，而不是由「层级数字」决定。** 不能表述为「卡在第 3 层（item strata）」——
那是结果，不是理由。

- 当前实际边界落在 **item strata 层（display_level 3）**，是因为：
  1. 这一层是 BLS 官方**稳定发布、且覆盖世纪窗口**的最细粒度；
  2. 再往下是 **ELI 层（Entry Level Item，display_level 4+，series 以 `SS` 前缀开头）**，其数据覆盖不足（见下方注脚），故不作为边界。
- 若有朝一日 ELI 层数据补全并覆盖世纪窗口，则按本原则，边界应继续下钻到 ELI 层——边界是「可移动的」，由数据覆盖决定。

**注脚 —— ELI 层为何不采用（「数据覆盖不全」，而非「更深所以不要」）：**
`cu.series` 中约 45 个 `CUUR0000SS` 开头的 ELI 系列，`begin_year` 极不均匀（1947–2011），
**多数 2000 年后才起步，覆盖不到 1998 世纪窗口**，无法参与跨世纪的 δ̂ 计算；
且这些 ELI 系列**全部挂在食品类下（不涉 N/R 分组）**。双重原因（覆盖不全 + 不进 N/R）下，ELI 层不进入检验集。
